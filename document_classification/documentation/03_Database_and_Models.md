# Database & Models Schema

The Construction AI platform uses PostgreSQL for its relational and JSONB storage capabilities. Below are the core Django models that power the Document Classification engine.

## 1. Document Fingerprinting (`DocumentFingerprint`)
To prevent redundant LLM processing and save cloud storage, we deduplicate uploads using SHA-256.
*   **Fields**: `hash` (unique string), `created_at`.
*   **Logic**: Before a file is saved to disk, its binary contents are hashed. If the hash exists, the API skips the upload phase and links to the existing `Document` record.

## 2. Core Document Model (`Document`)
This is the central source of truth for a file in the system.
*   **Identification**: `id` (UUID), `project_id`, `filename`, `storage_path`, `file_hash`, `fingerprint` (Foreign Key).
*   **Status Management**: 
    *   `status`: Uses the `DocumentStatus` TextChoices ENUM (`queued`, `classifying`, `classified`, `failed`, `needs_review`, etc.).
*   **Classification Results**:
    *   `doc_type`: The predicted document type (e.g., `contract`, `boq`, `rfp`, `drawing`).
    *   `classification_confidence`: The 0.0-1.0 confidence score returned by the LLM.
    *   `has_images`, `has_tables`, `has_drawings`: Boolean flags that determine downstream OCR processing logic.
*   **Error Handling**: `error_message`, `retry_count`.

## 3. Auditing & Performance Models (`audit.py`)
To ensure enterprise observability, every action taken by the AI is logged.

### `LLMUsageLog`
Tracks the financial and performance metrics of the LLM Factory.
*   **Fields**: `document` (FK), `model_name` (e.g., `llama-3.1-8b-instant`), `provider` (e.g., `groq`, `gemini`).
*   **Metrics**: `tokens_in`, `tokens_out`, `cost` (Decimal field for exact fractional dollar values), `latency_seconds`.
*   **Purpose**: This allows administrators to run aggregations (`Sum('cost')`, `Avg('latency_seconds')`) across thousands of documents to monitor AI budget consumption.

### `DocumentClassificationHistory`
Stores the exact output generated by the LLM before it gets parsed into the `Document` model.
*   **Fields**: `document` (FK), `classifier_name`, `raw_response` (JSONField).
*   **Purpose**: If the LLM hallucinates or misclassifies a document, engineers can inspect the `raw_response` to tune the prompt or debug the schema parsing.

## 4. Human-in-the-Loop (`ReviewTask`)
If the LLM confidence falls below a threshold (e.g., `< 0.75`), or if the LLM fails completely, a `ReviewTask` is generated.
*   **Fields**: `document` (FK), `status` (`pending`, `in_progress`, `resolved`), `reason` ("Low Confidence", "Pipeline Error").
*   **Purpose**: Allows human operators to view the uncertain document and manually assign the correct `doc_type`, which can then be used to fine-tune future models.
